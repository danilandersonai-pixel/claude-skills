---
description: Подобрать веб-референсы по теме — конвейер ref-finder → ref-curator → папка Markdown в ~/references/<тема>/
argument-hint: <тема> [тип: визуал/текст/тех/шрифты/палитры/эффекты] [стек, напр. Phaser 4]
---

Ты оркеструешь конвейер подбора референсов из интернета. Тема и параметры: **$ARGUMENTS**

Выполни по шагам:

1. **Разбери запрос.** Выдели тему. Если в аргументах указан тип референсов (визуал/текст/технический/функциональный/шрифты/палитры/эффекты/универсал) и/или стек проекта (например «Phaser 4») — учти их. Если тема пустая — спроси у пользователя, что искать, и остановись.

2. **Слаг папки.** Построй имя папки латиницей в kebab-case из темы (например «постапок пиксель-UI» → `postapoc-pixel-ui`). Целевой путь: `~/references/<слаг>/`. Если такая папка уже существует — сообщи пользователю и спроси: дополнять её или создать новую (`<слаг>-2`).

3. **Запусти искателя.** Вызови субагента `ref-finder` (Agent tool, subagent_type: ref-finder). Передай ему тему, тип (если есть) и контекст стека (если есть). Получи сырьё — структурированные блоки источников.

4. **Запусти куратора.** Вызови субагента `ref-curator` (Agent tool, subagent_type: ref-curator). Передай ему: всё сырьё от искателя, тему и путь `~/references/<слаг>/`. Куратор сам создаст папку, напишет README + файлы и проведёт верификацию (HEX через API Lospec, прозвон URL).

5. **Перепроверь сам.** После куратора лично убедись: папка и файлы на месте (`ls`), число источников совпадает, ссылки живые (прозвони `curl` на HTTP-статус), HEX палитр верны. Перечисли пользователю, что проверил (файлы ✓, URL ✓, HEX ✓).

6. **Отчитайся.** Дай путь к `README.md` кликабельной ссылкой, краткий вердикт куратора и честно отметь, чего в подборке не хватает.

Правила: не выдумывай URL и данные; если искатель вернул сомнительные ссылки — лови это на шаге 5; держи пользователя в курсе на каждом крупном шаге.
