# Tools Catalog — картотека инструментов

Живой реестр всех скиллов, плагинов и MCP-серверов пользователя. Решает
проблему «у меня есть инструменты, но я не помню какие». **Обновление = момент
просмотра**: каждый вызов пересобирает картотеку заново, поэтому она всегда
свежая (отдельного события «скилл добавлен» в Claude Code нет — это надёжный
эквивалент).

## Когда вызывать

- «Покажи мои инструменты / скиллы», «какие скиллы у меня есть», «что я умею»
- «Обнови картотеку / каталог», «/tools-catalog»
- Пользователь подбирает инструмент под задачу и хочет вспомнить, что доступно
- После установки нового скилла/плагина/MCP — чтобы зафиксировать его в базе

## Где живёт картотека

- **Источник правды (постоянный):** `CATALOG.md` в корне репо `claude-skills`
  — версионируется, виден на GitHub с любого устройства.
- **Живая копия:** `~/.claude/tools-catalog.md` — для быстрого локального
  доступа (в облаке эфемерна, перегенерируется при каждом вызове).
- **Реестр MCP:** `mcp-catalog.json` в репо `claude-mcp` — источник правды по
  MCP-серверам. Добавил сервер туда → вызвал картотеку → он в таблице.

## Workflow

### Шаг 1. Собрать файловый слой

Запусти скрипт (он рядом с этим SKILL.md). Подставь его реальный путь:

```bash
python3 "$SKILL_DIR/catalog.py" --out ~/.claude/tools-catalog.md
```

Скрипт сканит `~/.claude/skills`, `~/.claude/plugins`, проектные
`.claude/skills`, MCP-конфиги (`~/.claude.json`, `.mcp.json`, `claude mcp list`)
и печатает Markdown-таблицу.

**Источник MCP — реестр `claude-mcp`.** Скрипт автоматически читает
`mcp-catalog.json` из репо `danilandersonai-pixel/claude-mcp`, если он
подключён к сессии (ищет `/home/user/claude-mcp/mcp-catalog.json`,
`~/claude-mcp/...`, соседний с этим репо каталог, либо путь из переменной
`CLAUDE_MCP_CATALOG`). Серверы из реестра попадают в секцию MCP без
ручного парсинга `.mcp.json`. Формат — только метаданные (`name`,
`description`, `transport`, `command`, `env`, `scope`, `tags`), **без
секретов**. Если `claude-mcp` к сессии не подключён — реестр пуст, и MCP
нужно дополнить из текущей сессии (Шаг 2).

### Шаг 2. Дополнить инструментами текущей сессии ⚠️ ВАЖНО

В облачном/мобильном Claude Code скрипт видит НЕ всё — харнесс инжектит часть
скиллов и MCP-серверов помимо файловой системы. Поэтому:

1. Посмотри список доступных скиллов в `<system-reminder>` текущей сессии.
2. Посмотри подключённые MCP-серверы (их инструменты с префиксом `mcp__…`;
   при необходимости вызови `ToolSearch`, чтобы перечислить).
3. Добавь в таблицу всё, чего нет в выводе скрипта. Дедуплицируй по имени.

Так картотека получается полной и на десктопе, и в облаке.

### Шаг 3. Записать источник правды и показать

1. Запиши итоговую (объединённую) таблицу в `CATALOG.md` в корне репо
   `claude-skills`. Сохрани секции: **Скиллы / Плагины / MCP-серверы**, у
   каждой — счётчик и шапку с датой генерации.
2. Убедись, что `~/.claude/tools-catalog.md` содержит ту же итоговую таблицу
   (перезапиши, если дополнял после скрипта).
3. Покажи таблицу пользователю прямо в ответе.

### Шаг 4. Зафиксировать (если есть изменения)

Если `CATALOG.md` изменился — закоммить и запушь (можно через скилл `commit`).
Так база остаётся актуальной и видимой на GitHub.

## Формат таблицы

```markdown
## Скиллы (N)
| Инструмент | Описание |
|---|---|
| `имя` | краткое описание (до ~160 символов) |
```

## Правила

- Описания брать из фронтматтера `SKILL.md` (`description`), для MCP/плагинов —
  из манифестов или из знания о сервере; держать кратко (одна строка).
- Не выдумывать инструменты, которых нет ни в файлах, ни в сессии.
- Группировка строго по типам; внутри группы — по алфавиту.
